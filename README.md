# Bilingual Reader

英語の名作（著作権切れ）を、日本語訳を並べて読む自分用の英語学習ウェブアプリです。スマホ（Android の Chrome）で使うことを前提にしています。

- 英文の段落ごとに日本語訳を表示します（「和訳を隠す」で英文だけにもできます）。
- **単語をタップ**すると、画面下に **その文の中での意味**、**他によく使われる意味**、**その単語を使うイディオム・成句** を表示します。
- **同じ単語をもう一度タップ**すると単語帳に登録します。
- **単語を長押し**すると、作品の先頭からその単語までを「読んだ」として記録します。
- 作品の最後にある **「読了」ボタン**を押すと、その作品を最後まで読んだことを記録します。同じ作品は何度でも読み返せます。
- 本棚の画面に、全作品を合算した **総単語数（延べ）** と **総語彙数（同じ単語は 1 回だけ）**、単語帳の件数を表示します。
- 読書記録と単語帳は **バックアップ**としてファイルに書き出し、あとで読み込んで戻せます。
- 作品を開くと、続き（まだ読んでいない最初の単語がある段落）から表示します。
- 記録はすべて **この端末のブラウザの中だけ**（localStorage）に保存します。サーバーへは何も送らず、次に開いたときもそのまま残っています。
- 一度開けば、オフラインでも読めます。

## 収録作品

本棚は CEFR（ヨーロッパ言語共通参照枠）のレベル順に並びます。レベルは語彙と文の難しさから付けた **目安** で、公式な認定ではありません。

| レベル | 作品 | 作者・年 | 語数 |
|---|---|---|---|
| A1 入門 | McGuffey's First Eclectic Reader（第 53〜62 課の抜粋） | William Holmes McGuffey, 1879 | 約 1,100 |
| A2 初級 | The Tale of Peter Rabbit（ピーターラビットのおはなし） | Beatrix Potter, 1902 | 約 970 |
| B1 中級 | The Selfish Giant（わがままな大男） | Oscar Wilde, 1888 | 約 1,660 |
| B2 中上級 | A Pair of Silk Stockings（絹のストッキング） | Kate Chopin, 1897 | 約 1,900 |
| C1 上級 | The Gift of the Magi（賢者の贈り物） | O. Henry, 1905 | 約 2,100 |
| C2 最上級 | The Masque of the Red Death（赤死病の仮面） | Edgar Allan Poe, 1842 | 約 2,400 |

本文はすべて Project Gutenberg のパブリックドメインの原文です。和訳と語義はこのアプリ用に新しく作成したものです（既存の日本語訳は使っていません）。

## 使い方

| 操作 | 動き |
|---|---|
| 単語をタップ | 画面下に「この文での意味」「よく使われる意味」（品詞つき）「イディオム・成句」を表示（単語は黄色で強調。イディオムが無い単語は省略） |
| 同じ単語をもう一度タップ | 単語帳に登録。単語帳には、あとで見返せるよう単語を含む 1 文も一緒に保存する（同じ文の同じ単語は二重に登録しない） |
| 単語・パネル以外をタップ、または × | パネルを閉じる |
| 単語を長押し（約 0.5 秒） | 作品の先頭からその単語までを既読にする。既読の単語は薄い色になり、最後に読んだ単語に緑の下線が付く |
| 既読の範囲より前の単語を長押し | 既読の範囲をその単語まで戻す |
| 長押し後に下に出る「取り消す」 | 直前の長押しをなかったことにする（押し間違い用） |
| 作品の最後の「読了（最後まで読んだ）」 | 読了を記録して本棚に戻る。次に開くと最初から読み返せる。押した直後の「取り消す」で戻せる |
| 「和訳を隠す / 表示」 | 日本語訳の表示を切り替える（設定は保存される） |
| 上の「単語帳」 | 登録した単語の一覧（新しい順）。「削除」で消せる |

長押しを「ここまで読んだ」に使うため、本文の英文は長押しで選択・コピーできません。

### 単語の数え方

数字は **すべての作品を合算** します。

- **総単語数** ＝ 読了した作品の全単語数（読了した回数ぶん）＋ 読みかけの作品で長押しした所までの単語数
  - 同じ作品を 2 回読了すれば 2 回ぶん数えます。
  - 読みかけの部分は「先頭から何語目まで読んだか」で記録しているので、長押しをやり直しても二重には数えません。「読了」を押すと、その作品の読みかけの分は読了の分に置き換わります。
  - 最後の単語を長押ししただけでは読了になりません（「読了を押してください」と案内が出ます）。
- **総語彙数** ＝ それらの中に出てきた単語の種類。どの作品で何回出てきても 1 回だけ数えます。大文字・小文字は区別しません。
- **活用形は原形にまとめて 1 語**として数えます（`ran` `running` → `run`、`children` → `child`、`was` `were` `is` → `be`、`farthest` → `far`）。所有格の `'s` も外します（`Giant's` → `giant`）。
  - 原形への対応表は `web/texts/lemmas.json` にあります。表に無い語は、そのままの形で数えます。
  - 代名詞の格変化（`he` / `him` / `his`）や `thou` / `thee` などは別の単語として数えます。
  - 単語をタップしたときのパネルと単語帳には、原形（例：`ran` なら「原形 run」）も表示します。
- `peach-trees` のようなハイフンでつながった語は `peach` と `trees` の 2 語として数えます。

### バックアップ

本棚の画面のいちばん下に、次のボタンがあります。バックアップには読書記録・読了の履歴・単語帳・和訳の表示設定が入ります。

| ボタン | 書き出し先 |
|---|---|
| ファイルに保存 | スマホ本体の **「Download（ダウンロード）」フォルダ** に `bilingual-reader-backup-2026-10-29.json` のような名前で保存されます。「Files」アプリなどで確認できます |
| 共有して送る | Android の共有画面が開き、**Google ドライブ・Gmail など好きな送り先**を選べます（ブラウザがファイルの共有に対応している場合だけ表示されます。端末によっては `.txt` として送られますが、中身は同じで読み込みにも使えます） |
| 読み込み | バックアップのファイルを選ぶと、確認のあとで **今の記録をそのファイルの内容で置き換え** ます |

- Download フォルダに置くだけでは、スマホを紛失・初期化すると一緒に消えます。機種変更に備えるなら「共有して送る」で Google ドライブなどに送ってください。
- このアプリ以外のファイルや壊れたファイルは読み込みません。読み込むときは必要な項目だけを取り出し、形式を確認します。

### 記録が消えるとき

記録はブラウザのサイトデータとして保存されます。次の場合は消えるので注意してください。

- Chrome の「閲覧履歴データの削除」で **Cookie とサイトデータ** を消したとき
- アプリを開いたことのあるアドレス（URL）を変えたとき（保存場所はアドレスごとに分かれています）

ホーム画面に追加しておくと、ブラウザの容量整理で自動的に消されにくくなります。

## スマホで使えるようにする（Render で公開）

スマホで使うには、`web/` フォルダを HTTPS のサイトとして公開します。[Render](https://render.com/) の **Static Site（静的サイト）** を使います。サーバー側の処理は一切ない静的なファイルだけなので、無料プランで公開でき、非公開のリポジトリのままでも使えます。

公開の設定はリポジトリ直下の `render.yaml`（Render の Blueprint）にまとめてあります。

- `web/` フォルダだけを公開する（テストや README は公開されない）
- セキュリティ用の HTTP ヘッダーを付ける（下の「セキュリティ」を参照）
- アプリ本体と本文データはキャッシュせず毎回確認させ、更新がすぐ届くようにする

### 初回の手順

1. [Render](https://dashboard.render.com/) に GitHub アカウントでログインします。
2. **New → Blueprint** を選び、GitHub の連携でこのリポジトリ（`chrome-extension-reading-english`）へのアクセスを許可して選びます。
3. ブランチは **`main`** を選びます（`render.yaml` でも `main` を公開するよう指定しています）。
4. `render.yaml` の内容（`bilingual-reader` という Static Site）が表示されるので、**Deploy Blueprint**（適用）を押します。
5. 数十秒で公開され、`https://bilingual-reader-xxxx.onrender.com` のようなアドレスが表示されます。

Render の Blueprint を使わず、**New → Static Site** から手で作ることもできます。その場合は **Build Command：空欄（または `echo "no build step"`）**、**Publish Directory：`web`** を指定してください。セキュリティ用のヘッダーは **Settings → Headers** で、`render.yaml` と同じものを追加します。

### 更新

`main` ブランチに変更がプッシュ（またはマージ）されると、Render が自動で公開し直します。作業用のブランチにプッシュしただけでは公開されません。スマホでは、アプリを開き直すと新しい版が読み込まれます。

### 注意

- アドレス（`https://〜.onrender.com`）を変えると、スマホに保存された記録は引き継がれません（保存場所がアドレスごとに分かれるため）。変える前に「バックアップ」で書き出し、新しいアドレスで読み込んでください。
- Render の静的サイトは、Web サービスのように使っていない間に停止すること（スリープ）はありません。
- アドレスを知っている人は誰でも開けます。中身は著作権切れの作品と和訳だけで、記録は各自の端末の中にしか無いので、他の人に見られて困るものはありません。

### ホーム画面に追加する

1. スマホの Chrome で公開したアドレスを開きます。
2. 右上の「︙」→ **ホーム画面に追加**（または「アプリをインストール」）を選びます。
3. 以後はホーム画面のアイコンから開けます。アドレスバーのない、アプリのような画面で開きます。

## PC で動作確認する

```sh
python3 -m http.server -d web 8000
# ブラウザで http://localhost:8000 を開く
```

ファイルを直接開く（`file://`）と本文を読み込めないので、必ずこのようにローカルサーバー経由で開いてください。Chrome の DevTools でスマホ表示（Ctrl+Shift+M）にすると、スマホに近い見た目で確認できます。

### 確認すること

1. 本棚に A1〜C2 のレベル別に 6 作品が並び、数字がすべて 0 になっている。
2. 作品を開き、単語をタップすると、下に意味と文が出る。別の単語をタップすると切り替わる。
3. 同じ単語をもう一度タップすると「単語帳に登録しました」と出て、「単語帳」の画面に表示される。
4. 2 段落目の最後の単語を長押しすると、下に「ここまで読みました」と出る。本棚に戻ると、総単語数と総語彙数が増えている。
5. ページを再読み込みしても、2〜4 の記録が残っている。
6. もう一度作品を開くと、3 段落目から表示される。
7. いちばん下の「読了」を押すと本棚に戻り、総単語数が作品の全単語数（1,660）になり、「読了 1 回」と表示される。
8. 「ファイルに保存」でファイルがダウンロードされる。その後「読み込み」でそのファイルを選ぶと、記録が戻る。

### 自動テスト

Node.js 18 以降で次を実行します。

```sh
npm install
npx playwright install chromium
npm test
```

スマホと同じ画面サイズのブラウザで実際に操作し、次のことを確認します。

- 全段落の全単語に意味が用意されているか
- 単語のタップで意味と文が出るか、2 回目のタップで登録されるか（重複登録しないか）
- 長押し（マウスと指の両方）で既読になるか、長押しで意味のパネルが開いてしまわないか
- 単語数・種類数（活用形をまとめた数）が正しいか、戻す・取り消すができるか、再読み込み後も残るか
- 活用形の対応表に矛盾がないか（原形がさらに活用形として登録されていないか）
- 読了で全単語が加算されるか、読み返すと総単語数だけ増えて総語彙数は増えないか、取り消せるか
- 複数の作品の数字が合算されるか（テスト用の作品を差し込んで確認）
- バックアップの保存・共有・読み込みができるか、別のファイルを読み込まないか
- 和訳の表示設定が保存されるか
- オフラインで開けるか
- ページ内でエラー（CSP 違反を含む）が出ていないか

## セキュリティ

- **サーバーなし・外部通信なし**：アプリは自分のサイトのファイルだけを読み込みます。外部のスクリプト、フォント、アクセス解析などは使いません。
- **記録は端末の中だけ**：読書記録と単語帳はブラウザの localStorage にだけ保存し、どこにも送信しません。バックアップのファイルも、自分で保存先や送り先を選んだ場所にだけ出力します。
- **読み込むファイルの検査**：バックアップの読み込みでは、このアプリの形式か確認し、決まった項目だけを長さを制限して取り出します。
- **Content Security Policy**：自分のサイト以外からのスクリプト・スタイル・画像の読み込みと、インラインスクリプトを禁止しています。Render では同じ内容を HTTP ヘッダーでも送り、他のサイトに埋め込まれること（`frame-ancestors 'none'`）も禁止しています。
- **その他のヘッダー**：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、カメラ・マイク・位置情報などを使わせない `Permissions-Policy`、HTTPS を強制する `Strict-Transport-Security` を付けています（`render.yaml`）。自動テストでも同じヘッダーを付けて動作を確認しています。
- **XSS 対策**：本文や単語帳の表示はすべて `textContent` 相当で行い、`innerHTML` は使いません。
- **秘密の情報がない**：API キーなどは存在しないので、公開しても漏れるものがありません。

## ファイル構成

```
render.yaml                 Render での公開設定（公開フォルダ・HTTP ヘッダー）
CLAUDE.md                   Claude で作業するときのルール（作品追加の手順など）
web/                        ← 公開するのはこのフォルダだけ
  index.html
  app.js                    画面・単語タップ・単語帳・読書記録・単語数の計算
  style.css
  sw.js                     オフライン対応（Service Worker）
  manifest.webmanifest      ホーム画面に追加するための設定
  icon-192.png, icon-512.png
  texts/
    index.json              本棚に並べる作品の一覧
    common.json             どの作品でも使う基本語の「この文での意味」の既定値（the, of など）
    dict.json               原形ごとの「よく使われる意味」と「イディオム・成句」
    lemmas.json             活用形 → 原形の対応表（単語の種類を数えるため）
    <作品ID>.json           作品ごとの本文・和訳・語義（6 作品）
test/web.cjs                ウェブアプリの自動テスト
```

### 作品データの形式

```jsonc
{
  "id": "selfish-giant",            // ファイル名と同じ
  "level": "B1",                    // CEFR の目安（A1〜C2）
  "title": "The Selfish Giant",
  "titleJa": "わがままな大男",
  "author": "Oscar Wilde",
  "year": 1888,
  "source": "Project Gutenberg eBook #902 …",
  "paragraphs": [
    {
      "head": "Lesson LIII",                                         // （任意）この段落の前に出す見出し
      "en": "EVERY afternoon, as they were coming from school, …",  // 原文
      "ja": "毎日午後、学校から帰る途中、…",                          // 和訳
      "g": { "afternoon": "午後", "used": "（used to で）以前はよく〜したものだ" }  // この段落での語義
    }
  ]
}
```

単語の意味は、その段落の `g` → `common.json` の順に探します。キーは小文字で、所有格は `giant's` のまま書いても `giant` でも見つかります。
同じ単語でも段落ごとに意味を書き分けられるので、文脈に合った意味を表示できます。

「よく使われる意味」と「イディオム・成句」は、作品に関係なく `dict.json` に原形ごとにまとめています。

```jsonc
"run": {
  "m": ["〔動〕走る", "〔動〕（会社・店などを）経営する", "〔動〕（機械が）動く"],  // よく使われる意味（多い順）
  "i": [["run out of", "〜を使い果たす"], ["run into", "〜に偶然出会う"]]       // イディオム・成句（無ければ []）
}
```

### 作品を追加するには

1. [Project Gutenberg](https://www.gutenberg.org/) などから、著作権の切れた英語の原文を選びます。
2. 段落ごとに和訳と語義（`g`）を付けた JSON を `web/texts/` に置き、`web/texts/index.json` にレベル順で 1 行追加します。新しく出てきた活用形は `web/texts/lemmas.json` に、新しく出てきた原形は `web/texts/dict.json` に追加します。
3. **和訳を見直して直します。** 訳を作ったのとは別の目で、全段落を英文と一文ずつ突き合わせ、誤訳・訳抜け・付け足し・名前や文体の不統一・不自然な日本語・語義（`g`）のずれを直します。**この見直しと修正が終わるまでは完成としません。**
4. `npm test` で、全単語に「この文での意味」と辞書の項目があるかを確認します。

この手順は `CLAUDE.md` にも書いてあり、Claude で作業するときはこれに従います。

和訳と語義の作成は手間がかかるので、作品名を指定してもらえれば、こちらで作って追加します。
